練習課題

同じ課題を人と AI の両方に作ってもらい、同じ基準で採点します。点が低かった所は、ルール・見本・検査に戻して直します（これがデザインハーネスの使い方です）。

関連ページチェックリスト

進め方

  1. 課題を1つ選び、「作るもの」「必要な状態」を渡す（AI には下の指示文を使う）
  2. できたものを ds_lint_html（HTML）と ds_lint_css（CSS）、または scripts/check_colors.py で検査する
  3. チェックリストと、課題ごとの「合格の条件」で採点する
  4. 落ちた項目を記録し、原因がデザインシステム側（ルールが無い・分かりにくい）ならルール・見本・検査を直す

採点（100点・80点以上で合格）

観点配点測り方
自動検査30ds_lint_html と ds_lint_css の error が合わせて 0 件で 30 点。1件ごとに −10 点。warning は 1件ごとに −2 点（最大 −10 点）
部品・トークン20「必ず使う部品」をすべて使っている。部品を作り替えていない
状態20「必要な状態」がすべてある（1つ欠けるごとに −5 点）
レイアウト15コンテナの幅・余白の決め方・スマホ幅で崩れない
ライティング・合格の条件15ライティングのルールと、課題ごとの「合格の条件」を満たす

AI への指示文（そのまま使える）

指示文

コードを表示コピーしました
あなたは OKA.L.C Design System を使って UI を作ります。
1. MCP の ds_get_overview を呼び、「AI への指示」と「守ること」を読んでください
2. 課題：{ここに課題の「作るもの」「必要な状態」を貼る}
3. 使う部品は ds_get_component で HTML を取り、クラスを作り替えずに使ってください
4. 足りない値やルールがあれば、推測で足さずに質問してください
5. 作ったら ds_lint_html（HTML）と ds_lint_css（自分で書いた CSS）で検査し、error が 0 件になるまで直してください
6. 最後に、次の形で報告してください（採点に使います）
   ・使った部品：部品の id と使った場所
   ・状態：課題の「必要な状態」ごとに「あり／なし」と、どこで見られるか
   ・ds_lint_html の結果：error と warning の件数
   ・チェックリスト（作った後）：各項目「満たした／満たしていない」と理由
   ・迷ったこと・足りなかったもの：推測で決めた所があれば必ず書く

課題1：ホームページ（施設名A）

公開サイトのトップページ。内容は実際の公開サイトのトップページを元にし、見た目はこのデザインシステムの部品とトークンだけで作る。サイトの部品（ヘッダー・キービジュアル・フッターなど）の使い方と、ページの骨組みを測る。

作るもの

  • 本文へスキップ・サイトのヘッダー（ロゴ・ナビ・電話・メニュー）
  • ヒーロー（見出し・リード文・写真のスライド・お悩みの入口）
  • お悩みカード
  • サービス案内（分類カード3件）
  • 施設について（文章・写真・営業時間表）
  • お知らせ（記事の一覧）
  • アクセス（地図・住所・行き方のアコーディオン）
  • 代表者紹介・代表者コラム（記事の一覧）
  • よくある質問（アコーディオン）
  • フッター・右下の固定ボタン（予約・ページの先頭へ）

必ず使う部品

  • ヘッダー（c-header・c-brand・c-nav）・スキップリンク（c-skip-link）・フッター（c-footer）・右下の固定ボタン（c-floating）
  • 骨格（l-wrap・l-section・l-section__head）
  • ヒーロー（p-hero）・お悩みカード（p-worry）・サービス案内カード（p-service）
  • 施設について（p-about）・営業時間表（c-table）・お知らせ（p-news・c-post-list）
  • アクセス（p-access）・行き方（p-route）・代表者紹介（p-director）・よくある質問（c-faq）
  • 動き：js/site.js（ヘッダー・メニュー・アコーディオン・スライド・u-reveal）

必要な状態

  • ふつう（981px 以上）
  • タブレット（980px 以下）・スマホ（620px 以下）：メニューが開閉できる

合格の条件（この課題だけのもの）

  • 公開サイトの導線のボタン（CTA）はピル型の c-button--pill（副の導線は c-button--pill c-button--ghost）
  • 内容は l-wrap に入れ、セクションは l-section で区切る
  • リンクの文字は行き先が分かる言葉（「こちら」を使わない）
  • 2つ目の分類カードは p-service__card--sage
  • p- のクラスをトップページ以外で使い回さない

課題2：問い合わせフォーム

入力・検証・送信完了までの流れ。ラベルセット・フォームの組み方・エラーの出し方を測る。

作るもの

  • お名前（必須）・メールアドレス（必須・形式チェック）・電話番号（任意）
  • お問い合わせの種類（ラジオ・必須）
  • お問い合わせ内容（テキストエリア・必須・256文字まで）
  • 個人情報の取り扱いへの同意（チェックボックス・必須）
  • ［前の画面に戻る］［送信する］
  • 送信完了（完了画面へ移る、または前の画面に戻して完了を知らせる。入力した内容をそのまま残さない）

必ず使う部品

  • ラベルセット（c-formset）
  • テキストフィールド（c-field）
  • ラジオ（c-choice--radio）
  • テキストエリア（c-textarea-box）
  • チェックボックス（c-choice）
  • エラーのまとめ（c-error-summary）

必要な状態

  • ふつう
  • 入力エラー（項目の下＋先頭のまとめ）
  • 送信中（ボタンの loading）
  • 送信完了

合格の条件（この課題だけのもの）

  • l-wrap l-wrap--narrow に入っている
  • 項目の間 24px・まとまりの間 48px
  • エラーは欄を離れたとき＋送信時。直すと消える
  • 入力例は「例：」で始まる

課題3：一覧＋検索＋空状態

データを検索して一覧で見る画面。画面の状態の出し分けを測る。

作るもの

  • 検索欄とボタン（同じ高さ）・件数
  • 一覧（表）。長いタイトルは「…」で省略し、ツールチップで全文
  • ページ送り

必ず使う部品

  • テキストフィールド（c-field）
  • ボタン（c-button）
  • 表（c-data-table）・省略表示（c-truncate）
  • ページ送り（c-pagination）
  • 空状態（c-empty）
  • スケルトン（c-skeleton）
  • アラート（c-alert）

必要な状態

  • 読み込み中
  • ふつう
  • 0件（初めて）
  • 0件（検索結果なし）
  • エラー（読み込み）

合格の条件（この課題だけのもの）

  • エラーと0件が別の見た目
  • 検索欄とボタンの高さがそろっている
  • ページ送りは9個まで

課題4：管理画面の記事一覧

記事の状態を見て、削除などの操作をする管理画面。状態の表示・確認ダイアログ・トーストを測る。

作るもの

  • 記事の一覧（タイトル・状態・更新日・操作）
  • 状態：下書き／公開中／公開予約（a-status）
  • 絞り込みのタブ（すべて・下書き・公開中・公開予約）
  • 行ごとの削除 → 確認ダイアログ → 完了トースト
  • 新規作成ボタン

必ず使う部品

  • タブ（c-tabs）
  • 表（c-data-table）
  • 記事の状態（a-status）
  • ボタン（c-button）
  • モーダル（c-modal）
  • トースト（OKALC.toast）

必要な状態

  • ふつう
  • 0件
  • 削除の確認
  • 削除中
  • 削除完了
  • エラー（削除できなかった）

合格の条件（この課題だけのもの）

  • 管理画面の骨格（a-shell・a-main）に入っている
  • 削除の実行ボタンは negative、ダイアログのタイトルは「〜を削除しますか？」
  • ダイアログに「×」を置かない
  • 状態は色の点だけでなく文字でも示す

課題5：設定画面

設定を変えて保存する画面。スイッチとチェックボックスの使い分け・保存の流れを測る。

作るもの

  • 通知のオン／オフ（すぐ反映）
  • 表示する言語（セレクト）
  • メールの受け取り方（ラジオ）
  • ［前の画面に戻る］［保存する］と、保存完了のトースト

必ず使う部品

  • スイッチ（c-switch）
  • セレクト（c-select）
  • ラジオ（c-choice--radio）
  • ボタン（c-button）
  • トースト

必要な状態

  • ふつう
  • 保存中
  • 保存完了
  • エラー（保存できなかった）

合格の条件（この課題だけのもの）

  • すぐ反映するものはスイッチ、保存ボタンで確定するものはラジオ・セレクト
  • 保存ボタンの primary の solid は1つ
  • 保存できなかったときは理由と次の行動を書く

課題6：公開サイトの記事（一覧と詳細）

課題4 の管理画面で公開した記事を、公開サイトで読む画面。サイトの外枠（ヘッダー・パンくず・フッター）と、記事の一覧・詳細の部品の使い方を測る。

作るもの

  • 記事の一覧のページ：ヘッダー・パンくず・ページの見出し・記事の一覧（日付・タイトル）・フッター
  • 記事の詳細のページ：ヘッダー・パンくず・記事（日付・見出し・本文）・一覧へ戻る・前後の記事・フッター
  • 本文には小見出し・段落・画像・箇条書きを入れる

必ず使う部品

  • スキップリンク（c-skip-link）・ヘッダー（c-header・c-brand・c-nav）・パンくず（c-breadcrumb）・フッター（c-footer）
  • 骨格（l-wrap・l-section）・下層ページの見出し（c-page-head）
  • 記事の一覧：c-post-list（「もっと見る」）か、c-data-table ＋ ページ送り（c-pagination）のどちらか。選んだ理由を報告する
  • 記事の詳細（c-post・c-post-nav）
  • 空状態（c-empty）
  • 動き：js/site.js（ヘッダー・メニュー）

必要な状態

  • ふつう（981px 以上）
  • タブレット（980px 以下）・スマホ（620px 以下）：メニューが開閉できる。一覧が崩れない
  • 一覧が0件
  • 前の記事・次の記事の片方が無い（最初と最後の記事）

合格の条件（この課題だけのもの）

  • ページの見出し（h1）は1ページに1つ。記事の詳細では記事のタイトルが h1
  • 日付は time と datetime。表記は「2026.09.24」
  • 一覧のリンクの名前は記事のタイトル。「こちら」を使わない
  • パンくずの今いるページはリンクにしない（aria-current="page"）
  • p- のクラス（トップページだけの部品）を使わない
