マークアップ契約（公開ページの出力HTML）

公開ページの HTML で、クラス名・ID・構造をどう書くかの約束です。

関連ページ命名規則サイト構成のルール

この文書の役割

site.css（1,190行）と site.js は、特定のクラス名とHTML構造を前提に作られている。 CMSが公開ページを出力する箇所は、この構造どおりに出す。

独自のマークアップにすると、次のようにこれまでの調整がすべて失われる。

独自実装した場合起きること
クラス名を変えるCSSが当たらず、無スタイルのHTMLが表示される
入れ子を変える2カラム・グリッドが崩れる
data- 属性を落とすsite.js の機能が止まる（「もっと見る」など）
id を変えるgetElementById が null を返し、その先で例外が出て機能ごと止まる

⚠️ 新しいCSSクラスを作らない。 既存クラスで表現できないものが出たら、 実装せず依頼者に報告する。

1. お知らせ・コラム 一覧

HTML

コードを表示コピーしました
<nav class="c-breadcrumb" aria-label="パンくずリスト"><div class="l-wrap"><ol>
  <li><a href="/">ホーム</a></li>
  <li aria-current="page">お知らせ</li>
</ol></div></nav>
<section class="l-section l-section--post">
  <div class="l-wrap">
    <div class="c-page-head"><h1 class="c-page-head__title">お知らせ</h1></div>
    <ul class="c-post-list__items c-post-list__items--wide c-post-list" data-step="10">
      <li><a class="c-post-list__item" href="/news/2026-08-05-01">
        <time class="c-post-list__date" datetime="2026-08-05">2026.08.05</time>
        <span class="c-post-list__title">記事タイトル</span>
      </a></li>
    </ul>
  </div>
</section>
決まりごと
data-step="10" は必須。 site.js がこれを見て11件目以降を隠し、「もっと見る」を作る
サーバー側でページネーションを実装しない。 公開側は全件出力してJSが送り出す
日付の表記は 2026.08.05（ドット区切り）。datetime 属性はISO形式
コラムは <time> ではなく <span class="c-post-list__date">No.8</span>
JS無効時に全件がそのまま並ぶこと（hidden はJSが付ける）

コラムの「No.」

  • 最新の記事が最大の番号。 総公開件数を N とすると、最新が No.N、次が No.N-1
  • 一覧・詳細・トップページの3か所すべてで同じ番号になること
  • ⚠️ 公開済み記事だけを数える。 下書き・予約中を含めると番号がずれる
  • ⚠️ 記事を削除すると以降の番号がすべて繰り上がる。 これは仕様。番号を固定値として保存しないこと

    </nav>
  </div>
</article>
決まりごと
l-wrap--narrow を忘れない。 本文の行長を抑えるための指定（760px）
c-post-nav は前後の記事が存在するときだけその <a> を出す。両方無ければ <nav> ごと出さない
c-post-nav__link--next が付くほうが古い記事（「前の記事」）。 クラス名と表示ラベルが逆に見えるが、CSSがこうなっているので合わせる。--next は grid-column: 2（右列・右寄せ）の意味
前後記事のナビは公開済み記事だけを辿る。 下書き・予約中を挟んでスキップする

📌 post-nav-prev は書かない

もとの契約書（マークアップ契約の元の文書 §5-2）の見本には class="c-post-nav__link post-nav-prev" と書かれていたが、 post-nav-prev は site.css に定義が無く、何の効果も無い。 接頭辞の規則からも外れている。現行の実装（article.html.twig）でも使っていない。

新しく書き足さないこと。

3. 本文（c-post__body）で使える要素

サニタイズのホワイトリストと、site.css が想定している要素は一致している。

要素CSSの指定
pmargin-bottom: 1.5em
h2 h3見出し。h2 はセクション見出しと同じ形（明朝＋左の短い線）
strongfont-weight: 700
a--wine-deep ＋ 下線
ul ol li箇条書き（下記の注意）
imgmax-width: 100%; height: auto; border-radius: 16px
figuremargin: 1.8em 0
picture sourceWebPフォールバック
br改行

⚠️ 箇条書きは CSS で点と番号を出している

.c-post__body と .c-faq__a に、サービス案内の .c-list と同じピンクの丸と、 CSSカウンタによる番号を用意してある。list-style を戻さない。

公開ページを出力するときに、本文の ul / ol に role="list" を付ける。 記号を CSS で描いているため、付けないと Safari の読み上げがリストと扱わないことがある。エディタの保存形式は変えず、公開側の出力で足す。

⚠️ u（下線）は site.css に指定がない

エディタでは使えるが、ブラウザ既定の下線になり、リンクと見分けが付かなくなる。 使うなら実装後に表示を確認すること。

画像

  • <picture> で出力し、width / height を必ず付ける（CLS対策）
  • 公開側の画像はすべてWebP
  • ⚠️ ロゴ・図版などフラットな画像は非可逆WebPだと逆に太る。 極端にサイズが増える場合は元形式を残す判断ができるようにしておく

4. よくある質問

HTML

コードを表示コピーしました
<nav class="c-breadcrumb c-breadcrumb--soft" aria-label="パンくずリスト">…</nav>
<section class="l-section l-section--post c-faq">
  <div class="l-wrap">
    <div class="c-page-head"><h1 class="c-page-head__title">よくある質問</h1></div>
    <nav class="c-toc" aria-label="このページの目次">
      <p class="c-toc__title">このページの内容</p>
      <ul><li><a href="#cat1">施設について</a></li></ul>
    </nav>
    <div class="c-faq__group" id="cat1">
      <h2>施設について</h2>
      <details class="c-faq__item" id="q1">
        <summary>
          <span class="c-faq__q" aria-hidden="true">Q1</span>
          <span class="c-faq__q-text">質問文</span>
          <svg class="c-icon--chev" width="16" height="16" viewBox="0 0 24 24" fill="none"
               stroke="currentColor" stroke-width="2.4" stroke-linecap="round"
               stroke-linejoin="round" aria-hidden="true"><path d="m6 9 6 6 6-6"/></svg>
        </summary>
        <div class="c-faq__a"><p>回答</p></div>
      </details>
    </div>
  </div>
</section>
決まりごと
c-breadcrumb--soft を付ける（FAQページだけ地の色が違うため）
c-toc はサービス案内と共有のコンポーネント。 site.js が固定・現在地ハイライト・送りボタンを担当する。構造を変えない
id="cat1" はグループID、id="q1" はページ内通し番号。グループをまたいで連番（Q1 … Q15）
c-faq__q の表示も同じページ内通し番号
<details> を使う。 JS無効でも開閉できるようにするため
c-toc の項目はグループ名。order 昇順
ページの見出しは c-page-head の h1（お知らせなど、ほかの一覧ページと同じ）。グループの見出しは c-faq__group の直下の h2（トップページの「よくある質問」の節の中では、節の見出し h2 の下なので h3）

c-faq__q（Q番号）の色は --wine-deep。 読ませるための文字であって、ブランドの見せ場ではないため。

5. <head> と共通部品

項目仕様
CSS/JSの ?v=site.css と site.js の中身から算出した8桁ハッシュ
canonical自己参照。サイトのオリジン ＋ パス
OGPog:title og:url og:description og:image。画像は assets/ogp.jpg 固定
スキップリンク<a class="c-skip-link" href="#main">
<main id="main">site.js とスキップリンクが前提にしている

🟠 CSS/JSを変えたら ?v= を打ち直す

打ち直さないと、利用者のブラウザが古いCSSを読み続ける。 算出方式を複数箇所で持たない。 食い違うとページによって別のURLでCSSを読むことになり、 キャッシュが効かなくなる。

🟠 サイトのオリジンを2か所で持たない

必ずずれる。1か所（設定ファイル）に置き、全員がそこを読む。

6. site.js が前提にしているフック

出力するHTMLが変わっても、以下は機能し続ける必要がある。

機能必要なフック

FAQのアコーディオンdetails.c-faq__item
ページ内目次.c-toc ＋ .c-faq__group[id] / .c-faq__item[id]

トップへ戻る.c-floating__top
ヒーロースライダー・リビール.p-hero__slide が2枚以上 ／ .u-reveal

🔴 site.js が参照する id を改名しない

site-header / mobile-nav / nav-toggle / floating-top / main

🔴 JSが付けるクラスとCSSが待つクラスをズラさない

7. やってはいけないこと

  • css/components.css / js/site.js を編集する（変更が必要なら提案に留める）
  • 新しいCSSクラスを作る（既存クラスで表現できないものが出たら、実装せず報告する）
  • 記事一覧にサーバー側ページネーションを実装する（公開側はJSの「もっと見る」方式）
  • サービス案内の詳細ページに関連リンクを追加する （合意事項。回遊率やSEOを理由に戻す提案は事前確認が必要）
  • 生成されたHTMLを直接編集する（再生成で上書きされる）
  • ブロックの見本のページを本番の一部として扱う（配信されない場所に置くもの）
