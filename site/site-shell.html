クラス：c-nav

HTML（PC のナビ・スマホのメニュー）

コードを表示コピーしました
<nav class="c-nav" aria-label="メインナビゲーション">
      <ul>
        <li><a href="#">お知らせ</a></li>
        <li><a href="#">サービス案内</a></li>
        <li><a href="#">施設について</a></li>
        <li><a href="#">代表者コラム</a></li>
        <li><a href="#">よくある質問</a></li>
      </ul>
    </nav>
<nav class="c-nav--mobile" id="mobile-nav" aria-label="モバイルナビゲーション">
  <a href="#">お知らせ</a>
  <a href="#">サービス案内</a>
  <a href="#">施設について</a>
  <a href="#">代表者コラム</a>
  <a href="#">よくある質問</a>
  <a class="c-button c-button--pill" href="#">項目A</a>
</nav>
  • 項目は お知らせ → サービス案内 → 施設について → 代表者コラム → よくある質問 の5つ（2026-10-18 から。お知らせをサービス案内の上へ移し、代表者コラムを代表者紹介の外の節にした）
  • ナビ順とページ内の並び順を一致させる。 押したら必ず下方向へ進む
  • 項目の間は 24px（--gap-6）。5項目でブランド名とぶつからないよう 32px から詰めた
  • 電話番号の上の小さい文字は「ご予約・お問い合わせ」（5項目にしたとき、ナビの場所を空けるため短くした）
  • c-nav--mobile は全画面。is-open で表示。z-index はヘッダー（200）より下の190 — ハンバーガーを押して閉じられるようにするため

アクセシビリティ

  • nav に aria-label（メインナビゲーション／モバイルナビゲーション）
  • スマホのメニューを開いている間は裏の本文を操作できない（inert）。Esc で閉じてメニューボタンへ戻る（js/site.js）

c-toc — ページ内目次

クラス：c-toc

見本

このページの内容

  • 項目A
コードを表示コピーしました
<nav class="c-toc" aria-label="このページの目次">
  <p class="c-toc__title">このページの内容</p>   <!-- 視覚的には非表示 -->
  <ul><li><a href="#" aria-disabled="true">項目A</a></li></ul>
</nav>

サービス案内の各ページ・サービス案内一覧・よくある質問で共有する。

HTML

コードを表示コピーしました
<nav class="c-toc" aria-label="このページの目次">
  <p class="c-toc__title">このページの内容</p>   <!-- 視覚的には非表示 -->
  <ul><li><a href="#oc">項目A</a></li></ul>
</nav>
仕様
枠カードにしない。 角丸・枠線・塗りなし。上下1pxの罫線だけ
項目連番（01, 02…）＋テキスト＋下線インジケーター。連番は --num 10.5px --blush
見出し・アイコン出さない。 「このページの内容」は読み上げにだけ残す
現在地is-current（JSのスクロール監視）。最下部では最後の項目を現在地にする
固定時is-stuck で背景が画面幅いっぱいに広がり、ヘッダーと地続きのバーになる。高さ PC 51px / SP 46px
送りボタン1行に収まらないときだけ c-toc__more をJSが生成（実質SPのみ）。右端まで来ると反転して先頭へ戻る
背景色ページの地色に合わせて --toc-bg で差し替える。よくある質問は --bg-soft

なぜこの見た目なのか — 以前はカード＋ピル型だったが、料金表示や他のUIに酷似しているという 依頼者指摘を受けて刷新した。行頭アイコンも「3本線＝ハンバーガーに見える」「縦バー＝不要」と 順に指摘を受けて撤去している。カード・ピル・アイコンを戻さない。

実装上の注意

  • 全幅の実現は ::before を calc((var(--vw) - 100%) / -2) で伸ばす。--vw はJSが clientWidth を実測 （100vw だとスクロールバー分だけ横にあふれる）
  • 着地位置は3種とも同じ式 — c-section-block / c-index__group / c-faq__group[id] すべて scroll-margin-top: calc(var(--toc-h) + 8px)。--toc-h はJSが実測する
  • 背景はJS無効でも不透明を敷いてある（固定中に本文が透けないように）

アクセシビリティ

  • nav に aria-label="このページの目次"。目次のタイトルは見た目では隠しても読み上げには残す
  • 今いる節は is-current と aria-current="location"（js/site.js）
  • 右端の送りボタンは状態に合わせて aria-label が変わる（js/site.js）

u- — ユーティリティ

HTML

コードを表示コピーしました
<p class="u-reveal">ダミーテキストA（js/site.js が画面に入ったときに is-in を付けて、ふわっと出す）</p>
<h1>項目A<span class="u-nowrap">「項目B」</span></h1>
<p>ダミーテキストB<br class="u-br-sp">ダミーテキストC（スマホ幅だけ改行する）</p>
<span class="u-num">000-000-0000</span>

5つしかない。増やさない。

クラス効果
u-nowrap折り返さない
u-num数字用書体（Outfit）
u-revealスクロールで下から現れる。JSが is-in を付ける
u-br-spSP幅でだけ効かせる改行。 PC幅では display: none で詰めて表示する
u-visually-hidden画面には出さず、読み上げにだけ伝える（例：表の「ー」に添える「休み」の文字）

余白や色のユーティリティは作らない。Tailwind 風のユーティリティを増やす方針は採っていない （禁止パターン の「ユーティリティを増やさない」）。

アクセシビリティ

  • u-reveal は「動きを減らす」設定の人には最初から表示する（js/site.js）
  • u-br-sp の改行は見た目だけで、読み上げには影響しない
