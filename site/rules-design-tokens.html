デザイントークン（色・書体・余白・角丸・影）

関連ページ色余白・角丸・影モーションブレークポイント

正本は tokens/tokens.json。 tokens/tokens.css はそこから作る生成物で、直接直さない。値の一覧は「基礎」の各ページ（色・文字・余白・角丸・影・モーション・レイアウト）が正本から自動で作っている。この文書は決まりと考え方をまとめたもの。

0. デザイン原則

ブランドトーン — 「親しみやすさ」と「清潔感」の両立。 ロゴのコーラルピンク（#FB4E76）を軸に、過度にポップにならない落ち着いた配色を保つ。 当事者が安心して情報にたどり着ける可読性・平明さを最優先する。

フォント使い分け — 見出しは明朝で和の品格、本文・UIはゴシックでモダンに、 数字・英字は Outfit でスタイリッシュに。

コントラスト方針 — 大きな文字・アイコンは --wine、小さな文字・リンクは --wine-deep。（--wine-deep は rose-550 #E23C63。白の上で 4.15:1 で、4.5:1 に届かないことを承知で決めた値）

意図的な逸脱 — 英字アイブロウの全廃、施設について周辺のドロップシャドウ削除、 フッター最小化。装飾よりも情報伝達を優先するという依頼者の方針。

1. 色 — プリミティブとセマンティックの2層

CSS

コードを表示コピーしました
/* プリミティブ: 色そのもの。役割を持たない。CSSから直接使わない */
--rose-500: #FB4E76;

/* セマンティック: 役割。CSSではこちらだけを使う */
--wine: var(--rose-500);

プリミティブ

色ごとに 50〜1000 の20段（一覧は 色）。番号は明度順（小さいほど明るい）。役割は持たないので、CSS からは直接使わない。

半透明が必要な箇所には -rgb 版がある（--rose-50-rgb / --rose-500-rgb / --mauve-950-rgb）。

セマンティック（主なもの。全部は 色）

分類トークン指す先用途
ブランド--wine--rose-500ブランド色。ピル型ボタンの塗り・アクセント・大きめの文字（角型の主ボタンの塗りは --primary-solid）
--wine-deep--rose-550ホバー・リンク・強調文字・小サイズ文字（白の上で 4.15:1。基準未満を承知のうえでの決定）
--wine-tint--rose-200薄ピンク背景。ホバー面・アイコン背景
--blush--rose-400ボーダーホバー・装飾ライン

--bg-soft--rose-100セクション背景・ホバー面・料金の塗り
--panel--gray-0カード・ヘッダー・フッター背景
--ink--mauve-900本文テキスト
--ink-soft--mauve-500補助テキスト・ラベル・注記
--line--rose-300ボーダー・区切り線

--sage-tint--green-100同アイコン背景

--on-fill--gray-0塗りの上に載る文字
--shadow-ink--mauve-950-rgb影の濃色。--ink とは別の値

🔵 --wine の明るさを勝手に変えない

#FB4E76 に白文字を載せると 3.25:1 で、WCAG AA（4.5:1）を満たさない。

⚠️ 検査で不合格として再指摘されても、独断で暗くしないこと。

代わりに、文字として読ませる場面では --wine-deep（rose-550・白の上で 4.15:1）を使う。（--wine-deep は rose-550 #E23C63。白の上で 4.15:1 で、4.5:1 に届かないことを承知で決めた値）

使う色理由
ブランドの見せ場（ボタン・CTA）--wineブランドカラーを優先。不合格を承知で維持
本文へスキップ--wine-deep支援技術のための機能（白文字 4.15:1。ユーザーの決定で他の --wine-deep とそろえた）
FAQの通し番号 Q1--wine-deep読ませるための文字であって、ブランドの見せ場ではない
小さいピンク文字・現在地・ホバー--wine-deep文字なので --wine より濃い色を使う（4.15:1）

白地での文字色のコントラスト

トークンコントラスト
--ink13.89:1
--ink-soft5.07:1
--wine-deep白の上 4.15:1・ページの地（--bg）の上 3.98:1・料金の塗り（--bg-soft）の上 3.71:1・--wine-tint の上 3.58:1（4.5:1 未満。ユーザーの決定）

--sage は 3.85:1 で未達。文字色に使わない（枠線・面・アイコンには使ってよい）。

🔴 色の直書きは0件を保つ

HEX・rgb()・rgba()・hsl() を :root の外に書かない。 半透明は -rgb 版を使う。

CSS

コードを表示コピーしました

🔴 プリミティブを直接参照しない

var(--rose-500) のようにCSS本文から直接使わず、必ずセマンティック名を経由する。

--sans'Zen Kaku Gothic New', "Hiragino Sans", …本文・UI・h3
--num'Outfit', var(--sans)数字・英字ラベル・電話番号・日付

フォントは3種のみ。4種目を追加しない。

h1〜h4 は --serif が基本だが、h3 だけ --sans（カード見出し等をモダンに）。 管理画面は h1〜h4 すべて --sans。

文字サイズ・行間

文字サイズは --font-*（整数 px の段）、行間は --lh-*（8段）、太さは --fw-*（400・500・700）を使う。本文は 16px（--font-def）・行間 1.85（--lh-body）。段の一覧は 文字。

🟠 文字サイズの段を増やさない

上の表にない値を持ち込まない。必要になったら既存の段で代用できないか先に検討する。

3. レイアウト・角丸・影

CSS

コードを表示コピーしました
--container-lg: 1180px;      /* .l-wrap の最大幅。padding 0 32px（≤620px で 0 20px） */
--radius-lg: 24px;   /* カード・地図・ヒーロースライダー */
--radius-md: 16px;   /* 営業時間カード・FAQアイテム */
--radius-sm: 8px;    /* タグ・小UI・price系・押せるもの全般 */
--shadow:    0 24px 48px -28px rgba(var(--shadow-ink-rgb), .32);  /* 強調 */
--shadow-sm: 0 10px 24px -16px rgba(var(--shadow-ink-rgb), .28);  /* 通常（迷ったらこれ） */

⚠️ --shadow-md は存在しない

書いても効かない。強い影は --shadow、通常は --shadow-sm。

トークンでない角丸（意味を持つもの）

値意味
999px押せない。状態の表示（ボタン・ピル・バッジ・トースト）
--radius-sm（8px）サービスリンク・コラム・ルートカード・FAQバッジ
--radius-md（16px）お悩みアイコンの背景
50%丸ボタン・ドット

独自の数値を新しく持ち込まない。

4. 余白 — 4の倍数だけ

padding / margin / gap はすべて4の倍数。

2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 96 px（--p-* ／ --m-* ／ --gap-*）
段（トークン）主な用途
4 8（--p-1 / --p-2）アイコンと文字の隙間、行内の小さな間隔
12 16（--p-3 / --p-4）要素間、カード内の行間、グリッドの標準 gap
20 24（--p-5 / --p-6）囲みの内側（SP / PC）、サービス案内カードの gap
32（--p-8）.l-wrap の左右余白、2カラムの gap
40 48（--p-10 / --p-12）群の上下、下層セクションの余白
64 96（--p-16 / --p-24）セクション単位の余白

余白は --p-*（内側）・--m-*（外側）・--gap-*（間隔）のトークンで書く。段はこの表の値だけ。

管理画面（admin.css）で使うのは 4〜48px の範囲まで。 56px 以上はセクション単位の余白なので、管理画面では不要。

🔴 機械的に強制されている

コマンド

コードを表示コピーしました
python3 scripts/check_rules.py

対象は padding / margin / gap のみ。 角丸・影・font-size は対象外（ピルの 999px など4の倍数でない正当な値があるため）。

🟠 余白はトークンで書く

内側の余白は --p-*、外側は --m-*、並びの間は --gap-*（値は上の段と同じ）。数値で書く所があっても4の倍数にする（scripts/check_rules.py が調べる）。

🟠 新しい段を増やさない

上の段にない値を持ち込まない。必要になったら、既存の段で代用できないか先に検討する。

6. インタラクションの標準

コンポーネントを作るときは Default / Hover / Focus / Active を最低限定義する。

状態標準
Hover（面）背景 --bg-soft、文字 --wine-deep、必要に応じ枠線 --blush
Hover（浮き）カードは translateY(-6px) ＋ --shadow、ボタンは translateY(-2px)
Focus:focus-visible { outline: 3px solid var(--wine); outline-offset: 3px } ＋ 内側に白い線（box-shadow: 0 0 0 3px var(--panel)。入力欄は除く）。css/base.css が全体に付ける
Openアコーディオンは [open] で背景 --bg-soft ＋ シェブロン180°回転
Disableddisabled（リンクは aria-disabled="true"）を付ける。押せない見た目と :hover の打ち消しは部品（c-button・c-field など）が持っている

7. モーション

種類定義
スクロールリビール.u-reveal { opacity: 0; translateY(18px) } → IntersectionObserver（threshold 0.12）で .is-in
ナビ下線::after を scaleX(0) → (1)（--duration-slow）
カードホバーtransform / box-shadow（--duration-slow）、translateY(-6px) ＋ --shadow
ボタンホバーピル型だけ translateY(-2px)（--duration-def）。角型は色だけ変わる
ヒーロースライダーopacity（--duration-fade）のクロスフェード・5秒間隔
アコーディオン高さ（--duration-slow）のアニメーション（FAQ・ルート）

すべて prefers-reduced-motion: reduce で無効化・即時化する。

8. ブレークポイントは3つ

名称値主な変更
ヘッダーだけ≤1100pxナビ→ハンバーガー（電話番号は残す）。ロゴ・施設名・ナビ・電話番号が1行に収まらず重なるため
タブレット≤980pxヒーロー/当施設/代表者/お知らせ/アクセスを1カラム化
モバイル≤620px.l-wrap の左右の余白 32→20px。ヘッダー各要素を縮小し電話ラベルを1行維持。営業時間テーブルを縮小して横スクロールを解消

🟠 4つ目を増やさない

段は 980・760・620px の3つ（--bp-lg / --bp-md / --bp-sm）＋ヘッダーだけの 1100px（--bp-header。ヘッダー以外に使わない）。CSS の @media と JS の matchMedia は scripts/check_rules.py が調べる。

9. アクセシビリティ

  • スキップリンク（.c-skip-link・フォーカスで表示）
  • :focus-visible のリング（3px solid --wine ＋ 内側の白い線）。outline: none にしない
  • prefers-reduced-motion 対応
  • 装飾SVGに aria-hidden="true"、iframe に title、 ハンバーガーに aria-expanded の動的更新、aria-controls / aria-label / aria-labelledby
  • 指で押すところは 44px角を下回らせない
  • 状態は色だけで伝えない（形も変える）
  • 外部リンクは原則同一タブ遷移（target なし）。別タブは注記文リンクのみで、 その1件に rel="noopener" を付ける

10. 実装チェックリスト

  • [ ] 色はトークン（var(--wine) 等）で参照し、HEX直書きが無いか
  • [ ] プリミティブを本文から直接参照していないか
  • [ ] 見出しは --serif（h3 は --sans）か
  • [ ] 余白（padding / margin / gap）はトークン（--p-* / --m-* / --gap-*）か。新しい段を増やしていないか
  • [ ] 標準セクションの縦余白は l-section（上下 --p-24＝96px）か
  • [ ] カード・リンクに transition とホバー状態を定義したか
  • [ ] インタラクティブ要素に :focus-visible が効くか
  • [ ] スクロールインする要素に .u-reveal を付けたか
  • [ ] 装飾SVGに aria-hidden を付けたか
  • [ ] prefers-reduced-motion で破綻しないか
  • [ ] 1100px / 980px / 620px（特に 375px幅）でヘッダー・営業時間テーブル・ヒーローが破綻しないか
  • [ ] 写真・スライダーがコンテナ枠からはみ出していないか（横スクロールが出ないか）
