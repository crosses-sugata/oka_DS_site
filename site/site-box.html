囲み・カード・料金・表

関連ページ公開サイト管理画面色
この文書がいちばん事故が起きやすい。 塗りの色に意味を持たせているため、
見た目の選び方を間違えると内容が誤って伝わる（料金でないものが料金に見える）。

塗りの意味（最初に読む）

見た目意味クラス実装
ベージュの塗りここに料金があるc-price / c-card--pricedbackground: var(--bg-soft)
白い囲みそれ以外すべてc-checklist / c-card / c-contact / c-linkcard / c-price--plainbackground: var(--panel) + 1px var(--line)
白＋破線当施設で対応していないc-card--unavailableborder-style: dashed + var(--mute-line)
左の線だけ本文より弱いトーンの補足c-noteborder-left: 3px var(--blush)

白い囲み4種の装飾は1つのCSSルールで共有している。

CSS

コードを表示コピーしました
.c-checklist, .c-card, .c-contact, .c-linkcard {
  background: var(--panel); border: 1px solid var(--line);
  border-radius: var(--radius-md); padding: var(--p-5) var(--p-6);
}
  • 囲みを1つ増やすときは、まずこのセレクタに足せないか考える。 別々に書くと枠線の色と余白が微妙にズレる（実際にズレていた）
  • 装飾を変えると4種すべてが動く。1つだけ変えたいときは、それが本当に別種なのかを先に確認する

アクセシビリティ

  • カードの名前（c-card__name）で何のカードか分かるようにする
  • 対応していないカードは破線だけでなく「当施設では対応していません」の文字で伝える

クラス：c-card c-cards

ダミーテキストA

  • ダミーテキストB
コードを表示コピーしました
<div class="c-cards">
  <div class="c-card c-card--priced">
    <div class="c-card__head">
      <p class="c-card__name">項目A</p>
      <p class="c-card__sub">ダミーテキストA</p>
    </div>
    <p class="c-card__price">0,000円（税込）</p>
    <p class="c-card__desc">ダミーテキストA</p>
    <ul class="c-card__meta"><li>ダミーテキストB</li></ul>   <!-- 行頭に「※」が自動で付く -->
  </div>
</div>

用途: 利用者が選べる方法・メニューを並べる。8ファイルで使用。

データの書き方（サービス案内のデータ）

JSON

コードを表示コピーしました
{ "type": "cards", "items": [
  { "name": "…", "sub": "…", "price": "0,000円（税込）", "price_note": "…",
    "desc": "…", "meta": ["…"], "available": false }
]}
キー効果
price付けると c-card--priced（ベージュの塗り）に自動で切り替わる
available: falsec-card--unavailable（破線）＋「当施設では対応していません」バッジ

使う

  • 料金はカード側に書く。方法カードと料金表に同じ名前を2度出さない
  • meta は「※」付きの補足。行頭記号はCSSが付けるので、テキストに「※」を書かない
  • カードが1枚でも c-cards で包む（間隔の管理が c-cards 側にあるため）

使わない・してはいけない

  • ❌ 方法と料金を別々の枠に分けない。 1ページに同じ名前が2度出て、どちらが正か分からなくなる
    • 例外: ページA。方法カード（方法A／方法B）と費用表（条件A／条件B）は軸が違うため分けたまま。まとめると条件と方法が対応しているように読めてしまう
  • ❌ available: false を出典なしに付けない。バッジが無いカードを「実施している」と断定しているわけではない
  • ❌ c-card--unavailable の面をグレーに塗らない。バッジの文字が意味を伝えるので面は白のまま（グレーの濃さを4段階試したうえでの結論）
    • どうしても塗るなら #F4F1F1 より暗くしない。カード内の「※」注記（--ink-soft 13px）が 4.5:1 を割る
  • ❌ 対応していないカードの名称を薄くしない（--ink のまま）。読みにくくするのが目的ではない

    JSON

    c-price__items — 料金の行の中に置く条件

    CSS

    コードを表示コピーしました
    .c-price__items { margin-top: var(--m-2); display: grid; gap: var(--gap-1); }

    1行の料金に条件が複数ぶら下がるとき。li::before に印が付く。 行そのものを増やさず、条件はここに入れる（金額の対応が読めなくなるため）。

    条件の例（「例）〜の場合は〜円」など）を添えるときは、箇条書きの後ろに c-price__note を置く（同じ行の中の一番下。罫線は引かない）。表全体にかかる注記（c-note--box・罫線で区切る）とは分ける。行は左＝文・右＝料金の2列で、文が長いときは文の列の中で折り返し、料金は右に残す（2026-10-18 ユーザーの指示）。

    CSS

    コードを表示コピーしました
    .c-data-table { background: var(--panel); border: 1px solid var(--line);
           border-radius: var(--radius-md); overflow: auto; }

    ⚠️ overflow は常に付ける

    付けないと中の <table> のセル背景が角の外まで描かれ、角丸が欠けて見える。

    列名は表の枠の上端に貼り付く

    1列目（タイトル）だけを可変にし、残りは内容ぶんの幅で固定する。 中身の文字数で幅が変わると、お知らせと代表者コラムで列位置がズレて見比べにくい。

    c-data-table__col--group表の幅の 25%（最小 96px）グループ。中身は c-truncate で包み、狭くなったら1行で「…」にする（全文はツールチップ）

    c-data-table__col--date120px公開日・更新日
    c-data-table__col--count120px件数（例：グループの「質問の数」）。セルは c-data-table__cell--count、620px 以下でタイトルの下に出すのは c-data-table__row-count（日付と同じ畳み方）
    c-data-table__col--ops中身ぶん（1%）操作のボタンが並ぶぶんだけ。右端に寄せ、余った幅はタイトルへ

    colgroup を持たない表は、.c-data-table table:not(:has(col)) の指定で 2列目以降が内容ぶんの幅（width: 1%）まで縮む。

    長いタイトルを「…」で省く（c-data-table__cell--title + c-truncate）

    クラス：c-data-table__cell--title c-truncate

    省略は公開サイトと同じ c-truncate（モーダル・ツールチップ）。「…」になったときだけ全文のツールチップが出て、キーボードでも読める。title 属性は使わない（マウスでしか読めない）。

    ⚠️ max-width: 0 を消さない

    テーブルのセルは中身に合わせて広がるので、幅の上限を決めないと省略が効かない。 max-width: 0 は「余った幅だけをもらう」の意味で、min-width: 200px が下限を守る。

    ⚠️ セレクタを td:first-child に戻さない

    よくある質問では左端が Q番号の列。:first-child にすると省略が Q番号に当たり、 タイトルは省略されなくなる。

    一覧表の狭い画面での振る舞い

    幅何が起きるか
    ≤980px表は縮めずに横スクロール（min-width: 480px）。操作の列（c-data-table__col--ops）がある表だけ、その列が右端に sticky で貼り付く（管理画面）。操作の列が無い表（公開サイトの記事一覧など）は貼り付けない
    ≤620px公開日の列を隠し（c-data-table__col--date / c-data-table__cell--date）、代わりに c-data-table__row-date をタイトルの下に出す。表の下限は300px

    列の並べ方

    • 管理画面：タイトル → 状態 → 日付 → 操作（右端）。タブレット（≤980px）では操作の列が右端に貼り付く。スマホ（≤620px）では列名の行を見た目だけ消し、内容の列（タイトル／状態と日付）と操作の列（ゴミ箱のアイコン）の2列に畳む（管理画面の見本）
    • 公開サイトの記事一覧：日付（左端） → タイトル → 分類。操作の列は無い。スマホ（≤620px）では日付の列を消し、タイトルの下に日付を出す（c-data-table__row-date を書いておく）

    ⚠️ 列を詰めて折り返させない

    タイトルが1文字ずつ折り返すと、一覧として読めなくなる。 480px は、タイトル・状態・日付の列が読める下限の目安。
