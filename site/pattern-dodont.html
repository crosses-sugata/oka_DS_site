良い例・悪い例

よくある間違いを並べました。右下の「検査」は、MCP の ds_lint_html で見つけられるルールの名前です（無いものは目で確かめます）。

関連ページ禁止パターンライティング

色・見た目

良い例

color: var(--ink);
background: var(--primary-solid);

役割の名前が付いたセマンティックトークンを使う

悪い例

color: #2A2224;
background: var(--rose-600);

HEX やプリミティブを直接書くと、色の変更についていけない

検査：color-hex / color-primitive

良い例

ページA

リンクは下線付き

悪い例

ページA

色だけでは、色の見分けにくい人にリンクと分からない

良い例

押したときは色だけ変わる

悪い例

大きさが変わる動きは NG（周りの部品がずれて見える）

検査：motion-scale

ボタン・入力欄

良い例

入力欄（lg）とボタン（lg）で高さがそろう

悪い例

違う高さを並べるのは NG

検査：align-height

良い例

アイコンだけのボタンには aria-label で名前を付ける

悪い例

名前が無いと、読み上げで「ボタン」としか伝わらない

検査：a11y-icon-button

良い例

何が起きるか分かる動詞

悪い例

「OK」では何が起きるか分からない

検査：writing-button

エラー・通知

良い例

メールアドレスの形式で入力してください

赤い枠 ＋ アイコン ＋ 何をすればよいかの文字

悪い例

赤い枠だけでは、色の見分けにくい人に伝わらず、直し方も分からない

検査：a11y-error-text

良い例

項目Aを削除しますか？

この操作は元に戻せません。

何をするかが具体的。閉じるのは汎用ボタン

悪い例

本当によろしいですか？

何を確認しているか分からない。「×」と OK が並ぶ

検査：writing-dialog / modal-close-icon / writing-button
